## 글꼴 길목 (2026-10-18)
- `0x80032E3C` (실행 파일, 상주) = 글리프 주소 함수: a0 = SJIS u16 → v0 = BIOS 30 B 글리프(16×15 1bpp) 주소. 안에서 BIOS 썽크 0x8003391C 를 세 곳에서 부름(0x8140 공백 처리·기호/가나 구간·한자 구간).
- 실행 파일 안 호출 0. 호출은 **메뉴 오버레이**(TRAIN.PAC 0x4B800~0x63800 → RAM 0x801BF000~0x801D7000, 스테이트 RAM 대조로 확정) 0x801D5244·0x801D5318.
  - 0x801D51EC: 문자열(0 끝) 2바이트씩 → 글리프 → 0x801D536C(16×15 → 그림) → LoadImage 0x80030534, x += 4… 문자표(미리 굽기) 없음 → 글자마다 즉석.
  - 0x801D52B8: 한 글자 판, 0x801C22D8 의 코드와 같으면 게임 자체 글리프 0x801DBDD8 를 씀(자체 글자 바꿔치기 선례).
- ⇒ 한글 내장 = 0x80032E3C 입구 가로채기: 우리 코드 범위면 내장 글리프 주소, 아니면 원래 길.
- 메뉴 오버레이 평문 = TRAIN.PAC 0x4B8EC~(자료관 설명 등).
- ⏳게임 중 발차 안내판(今度の発車は)도 BIOS 글꼴인데 TRAIN.PAC 에서 0x80032E3C 호출이 메뉴 오버레이 2곳뿐 → 게임 중 오버레이는 압축이거나 다른 길. 다음 조사.

## 빈 RAM 후보 (스테이트 30개 모두 0)
- 0x80170F60~0x801BF000 (312 KB, 메뉴 오버레이 바로 앞) · 0x801013B0~0x80108B00 (29 KB) · 0x801FBCFC~0x801FFB50 (15 KB) 등.
- ⚠️«스테이트에서 0» ≠ 빈 곳 — 그 구역에 실리는 파일 최대 크기로 다시 판정할 것.
- 메뉴 오버레이(0x801BF000)는 게임 중에도 그대로 상주(스테이트 18·20·25). 게임 중엔 0x80110000~ 에 노선 자료(PAC 0x1E3500 등, 노선마다 다름)가 실림 → 0x80170F60~ «빈 곳»은 다른 노선에서 덮일 수 있음 ⏳노선 자료 최대 크기로 판정.
- 두 번째 길: 오버레이 0x801D4DD4 가 **BIOS 썽크 0x8003391C 를 직접**(a0 = 본문 SJIS). 반면 0x80032E3C 는 썽크에 기준 코드(0x8140·0x889F)만 주고 칸 번호는 스스로 계산.
- ⇒ 가로챌 곳 두 군데(둘 다 실행 파일 상주): 0x80032E3C 입구 + 썽크 0x8003391C. 우리 코드 범위면 내장 글리프 주소, 아니면 원래 길.

## 디스크 목차 = 실행 파일 안 «섹터 지도» (2026-10-18)
- `0x80047B70(n)`: LBA = 23 + Σ_{i<n} (크기[i] + (종류[i]∈{0x10,0x0D,0x0E} ? 0 : 1)). 종류 u8 표 0x80048468, 크기 u16 표 0x80048870(파일 0x39070).
  - 0번 = SYSTEM.CNF(2섹터), 1번 = SLPM(150), 2번~ = TRAIN.PAC 조각, 뒤로 TRAIN.SUB(종류 09·0F = 스트림 추정).
